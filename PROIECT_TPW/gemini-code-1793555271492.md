### 0.2. Scriptul SQL Extern pentru SQL*Plus (`init_db.sql`)
**De ce folosim un fișier extern `.sql` și tipul `INTEGER`?**
Conform cerințelor de examen, dezvoltarea nu se face pe conturile `SYS` sau `SYSTEM`, ci pe schema `student` cu parola `student`[cite: 23]. Crearea și popularea tabelelor trebuie realizate prin comenzi `CREATE TABLE` și `INSERT` rulate dintr-un fișier text extern în **SQL*Plus** înainte de pornirea aplicației, pentru a asigura portabilitatea bazei de date pe alt server SQL[cite: 22]. Coloanele numerice salariale se aleg de tip `INTEGER` în Oracle deoarece toate valorile calculate sunt rotunjite la întreg, ceea ce corespunde cu realitatea din domeniul salarizării[cite: 22].

Salvați codul de mai jos într-un fișier numit `init_db.sql` și rulați-l în **SQL*Plus**[cite: 22, 23]:

```sql
-- ==========================================================================
-- 1. Creare schema utilizator 'student' (Rulati ca SYSDBA doar prima data!)
-- ==========================================================================
ALTER SESSION SET "_ORACLE_SCRIPT"=true;
CREATE USER student IDENTIFIED BY student;
GRANT ALL PRIVILEGES TO student;

-- Conectare la contul student (ajustati serviciul XEPDB1 sau XE dupa caz)
CONNECT student/student@localhost:1521/XEPDB1;

-- ==========================================================================
-- 2. Stergere tabele vechi (daca exista) pentru reinitializare curata
-- ==========================================================================
BEGIN
   EXECUTE IMMEDIATE 'DROP TABLE ANGAJATI CASCADE CONSTRAINTS';
EXCEPTION WHEN OTHERS THEN NULL;
END;
/
BEGIN
   EXECUTE IMMEDIATE 'DROP TABLE PROCENTE CASCADE CONSTRAINTS';
EXCEPTION WHEN OTHERS THEN NULL;
END;
/
BEGIN
   EXECUTE IMMEDIATE 'DROP SEQUENCE SEQ_ANGAJATI';
EXCEPTION WHEN OTHERS THEN NULL;
END;
/

-- ==========================================================================
-- 3. Tabela PROCENTE (CAS = 25%, CASS = 10%, IMPOZIT = 10%, Parola)
-- ==========================================================================
CREATE TABLE PROCENTE (
    ID_PROC      INTEGER PRIMARY KEY,
    CAS_PROC     NUMBER(5, 4) DEFAULT 0.25 NOT NULL,
    CASS_PROC    NUMBER(5, 4) DEFAULT 0.10 NOT NULL,
    IMPOZIT_PROC NUMBER(5, 4) DEFAULT 0.10 NOT NULL,
    PAROLA       VARCHAR2(100) NOT NULL
);

-- Parola implicita 'Adevarat' conform exemplului din Cursul 2.1
INSERT INTO PROCENTE (ID_PROC, CAS_PROC, CASS_PROC, IMPOZIT_PROC, PAROLA)
VALUES (1, 0.25, 0.10, 0.10, 'Adevarat');

-- ==========================================================================
-- 4. Tabela Principala ANGAJATI (toate sumele sunt INTEGER conform cerintei)
-- ==========================================================================
CREATE TABLE ANGAJATI (
    NR_CRT         INTEGER PRIMARY KEY,
    NUME           VARCHAR2(50) NOT NULL,
    PRENUME        VARCHAR2(50) NOT NULL,
    FUNCTIE        VARCHAR2(50) NOT NULL,
    SALAR_BAZA     INTEGER NOT NULL,
    SPOR_PROC      INTEGER DEFAULT 0 NOT NULL,
    PREMII_BRUTE   INTEGER DEFAULT 0 NOT NULL,
    TOTAL_BRUT     INTEGER,
    BRUT_IMPOZABIL INTEGER,
    IMPOZIT        INTEGER,
    CAS            INTEGER,
    CASS           INTEGER,
    RETINERI       INTEGER DEFAULT 0 NOT NULL,
    VIRAT_CARD     INTEGER,
    POZA           BLOB
);

CREATE SEQUENCE SEQ_ANGAJATI START WITH 1 INCREMENT BY 1 NOCACHE;

-- ==========================================================================
-- 5. Trigger pentru Auto-Increment NR_CRT si Calcul Automat Salarii
-- ==========================================================================
CREATE OR REPLACE TRIGGER TRG_CALC_SALARII
BEFORE INSERT OR UPDATE ON ANGAJATI
FOR EACH ROW
DECLARE
    v_cas_proc     NUMBER(5, 4);
    v_cass_proc    NUMBER(5, 4);
    v_impozit_proc NUMBER(5, 4);
BEGIN
    IF INSERTING AND :NEW.NR_CRT IS NULL THEN
        SELECT SEQ_ANGAJATI.NEXTVAL INTO :NEW.NR_CRT FROM DUAL;
    END IF;

    IF :NEW.SPOR_PROC IS NULL THEN :NEW.SPOR_PROC := 0; END IF;
    IF :NEW.PREMII_BRUTE IS NULL THEN :NEW.PREMII_BRUTE := 0; END IF;
    IF :NEW.RETINERI IS NULL THEN :NEW.RETINERI := 0; END IF;

    SELECT CAS_PROC, CASS_PROC, IMPOZIT_PROC
      INTO v_cas_proc, v_cass_proc, v_impozit_proc
      FROM PROCENTE
     WHERE ID_PROC = 1;

    -- Formulele oficiale din Proiect-ASP.pdf:
    :NEW.TOTAL_BRUT     := ROUND(:NEW.SALAR_BAZA * (1 + (:NEW.SPOR_PROC / 100)) + :NEW.PREMII_BRUTE);
    :NEW.CAS            := ROUND(:NEW.TOTAL_BRUT * v_cas_proc);
    :NEW.CASS           := ROUND(:NEW.TOTAL_BRUT * v_cass_proc);
    :NEW.BRUT_IMPOZABIL := :NEW.TOTAL_BRUT - :NEW.CAS - :NEW.CASS;
    :NEW.IMPOZIT        := ROUND(:NEW.BRUT_IMPOZABIL * v_impozit_proc);
    :NEW.VIRAT_CARD     := :NEW.TOTAL_BRUT - :NEW.IMPOZIT - :NEW.CAS - :NEW.CASS - :NEW.RETINERI;
END;
/

-- ==========================================================================
-- 6. Inserare Angajat de Test Obligatoriu (Popescu Ion -> Virat Card = 2574)
-- ==========================================================================
INSERT INTO ANGAJATI (NUME, PRENUME, FUNCTIE, SALAR_BAZA, SPOR_PROC, PREMII_BRUTE, RETINERI)
VALUES ('Popescu', 'Ion', 'Inginer', 4000, 10, 0, 0);

INSERT INTO ANGAJATI (NUME, PRENUME, FUNCTIE, SALAR_BAZA, SPOR_PROC, PREMII_BRUTE, RETINERI)
VALUES ('Ion', 'Ionica', 'Director', 9000, 15, 500, 200);

INSERT INTO ANGAJATI (NUME, PRENUME, FUNCTIE, SALAR_BAZA, SPOR_PROC, PREMII_BRUTE, RETINERI)
VALUES ('Dan', 'Daniel', 'Contabil', 5500, 5, 200, 150);

COMMIT;
```

### 1.2. Construirea Paginii `Site.master` (Header AJAX + Meniu Orizontal + Shortcut Panel + Contor `Application`)
**De ce este structurat astfel `Site.master`?**
* **Separarea structurii de conținut:** Pagina `Site.master` definește cadrul comun (antetul albastru, ceasul AJAX, imaginile aleatoare, bara de meniu și subsolul), în timp ce fiecare opțiune a aplicației se încarcă în interiorul controlului `<asp:ContentPlaceHolder ID="MainContent" runat="server">` („ZONA AFIȘARE” din schița proiectului)[cite: 5, 21].
* **Meniu ASP.NET (`<asp:Menu>`):** Conform îndrumarului `_2.1`, vechiul meniu HTML bazat pe lista `<ul>` se comentează sau se șterge și se înlocuiește cu controlul server `<asp:Menu ID="Menu1" runat="server" Orientation="Horizontal">`, folosind entități `&nbsp;` pentru spațierea opțiunilor principale și `<br>` pentru coborârea meniului[cite: 4, 5].
* **Zona de Header cu AJAX:** Conform cerinței 1 din `Proiect-ASP.pdf`, în antet folosim un `UpdatePanel` și un `Timer` pentru a afișa ceasul și data de pe serverul Web fără reîncărcarea întregii pagini, alături de 2-3 imagini afișate aleator (considerate cu titlul de reclame)[cite: 21].
* **Variabila `Application["nr"]`:** Spre deosebire de `Session[]` (care este individuală pentru fiecare utilizator), variabila `Application[]` are valabilitate globală la nivel de aplicație, putând fi mai multe sesiuni distincte care partajează simultan aceeași variabilă[cite: 8].

        imgReclama1.ImageUrl = _reclame[idx1];
        imgReclama2.ImageUrl = _reclame[idx2];

### 1.4. Autentificare (Protecție cu Parolă) folosind `Session` (`ProcenteLogin.aspx` & `ModifProcente.aspx`)
**De ce folosim `Session["parola"]` și `Server.Transfer` aici?**
În Cursul `_2.1` (punctul 4, Fig. 21 și Fig. 22) este prezentată exact metoda cerută la examen pentru protejarea paginii de modificare a procentelor[cite: 7, 8, 22, 23]:
1. Utilizatorul introduce parola într-o pagină portal (`ProcenteLogin.aspx`), care salvează valoarea în `Session["parola"] = TextBox1.Text;` și transferă execuția către pagina protejată prin `Server.Transfer("ModifProcente.aspx");`[cite: 7].
2. Pagina protejată (`ModifProcente.aspx`) citește în `Page_Load` variabila `Session["parola"].ToString()` în interiorul unui bloc `try-catch`[cite: 8]. ### 2.1. Rezolvarea Erorii `UnobtrusiveValidationMode` în `Web.config`
**De ce apare eroarea la rularea controalelor de validare?**
În .NET Framework 4.5+, controalele `RequiredFieldValidator`, `RegularExpressionValidator` și `RangeValidator` încearcă implicit să folosească validare bazată pe jQuery (`UnobtrusiveValidationMode`), generând eroarea: *„WebForms UnobtrusiveValidationMode requires a ScriptResourceMapping for 'jquery'”*[cite: 16, 17].

Conform **Soluției 1** din Cursul `_2.2` (pagina 9), deschideți fișierul `Web.config` și adăugați cheia `ValidationSettings:UnobtrusiveValidationMode` cu valoarea `None` în secțiunea `<appSettings>`, înainte de eticheta de final `</configuration>`[cite: 17]:

```xml
  <appSettings>
    <add key="ValidationSettings:UnobtrusiveValidationMode" value="None" />
  </appSettings>
</configuration>
```
*(Alternativ, conform Soluției 2 din curs, puteți adăuga atributul `UnobtrusiveValidationMode="None"` direct în directiva `<%@ Page ... %>` a fiecărei pagini care conține validatori[cite: 17].)*

### 2.2. Pagina `AdaugareAngajat.aspx`: Validatori + Auto-Apel `PostBack` pentru Calculul Salariului
**De ce folosim validatori pe partea de client (`EnableClientScript="True"`) și `PostBack`?**
* În cazul introducerii unor date incorecte, string-ul SQL devine incorect și interogarea eșuează[cite: 12]. Controalele de validare au proprietatea `EnableClientScript="True"`, rulând pe partea de client și **nemaifăcând PostBack spre server** dacă datele sunt invalide[cite: 12, 18].
* Folosim cei 3 validatori din Cursul `_2.2`[cite: 11, 12, 13]:
  1. `RequiredFieldValidator`: obligă la introducerea unor date în `TextBox`, fără a le verifica conținutul[cite: 12, 13].
  2. `RegularExpressionValidator`: verifică formatul cu o mască Regex (`^[a-zA-Z''-'\s]{1,40}$` pentru nume și `^\d+$` pentru valori numerice întregi pozitive)[cite: 11, 12, 13].
  3. `RangeValidator`: setează o plajă de valori permisă (`Type="Integer"`, `MinimumValue`, `MaximumValue`)[cite: 13].
* La apăsarea butonului de calcul/adăugare, se realizează un **PostBack implicit** (auto-apel POST către pagina apelantă însăși)[cite: 9]. Dacă `Page.IsValid` este `true`, calculăm în C# coloanele read-only (pe fundal galben) folosind formulele din `Proiect-ASP.pdf`, iar interfața rămâne deschisă pentru o nouă operare[cite: 9, 21, 22].

### 2.3. Transferul de Parametri între Mai Multe Pagini (`SursaTransfer.aspx`, `Tinta1.aspx`, `Tinta2.aspx`)
**Care este diferența dintre `Response.Redirect` și `Server.Transfer` la susținerea orală?**
Conform tabelului din Cursul `_2.2` (pagina 2)[cite: 10]:
1. **`Response.Redirect` (echivalent HTTP GET):** Redirecționează browserul către o nouă adresă URL care conține parametrii în *QueryString* (`Tinta1.aspx?parameter1=...&parameter2=...`), codificați cu `Server.UrlEncode(...)`[cite: 10]. **Adresa URL din browser se schimbă**, iar pagina destinație îi citește cu `Request["parameter1"]` sau `Request.QueryString[0].ToString()`[cite: 10].
2. **`Server.Transfer` (echivalent POST / Context pe server):** Transferul se face direct pe server[cite: 10]. Datele se salvează în `this.Context.Items["Param1"] = ...` înainte de `Server.Transfer("Tinta2.aspx", true)` și se citesc în pagina țintă cu `this.Context.Items["Param1"].ToString()`[cite: 10]. **Obs. importantă pentru examen:** La `Server.Transfer`, **NU se schimbă adresa URL în browser** (nu apare numele paginii destinație `Tinta2.aspx`)[cite: 10]!
